# Canton Daml Audit Kit

**Набор skills, rules и готовых скриптов для анализа Daml-контрактов с учётом специфики Canton. Работает в вашем привычном агентном харнесе: после подключения набора укажите только директорию проекта.**

[English overview](README.en.md)

Готовые скрипты выполняют повторяющуюся работу локально: индексируют исходники, находят точки для проверки, считают хеши, выбирают ограниченные фрагменты кода и собирают отчёт. Модель получает компактную сводку и нужные участки вместо повторного чтения всего репозитория и написания одноразовых сканеров. Это сокращает расход контекста и токенов; фиксированный процент экономии не обещается.

**Не нужно запускать у себя чужой недоверенный харнес.** Здесь нет отдельного агентного рантайма, оркестратора, прокси к модели, собственного LLM-клиента или сервера. Вы используете свой харнес, свою модель и свои правила доступа. Набор состоит из читаемых инструкций и небольших локальных инструментов. Просмотрите скрипты перед первым использованием согласно правилам вашей среды.

## Быстрый запуск в вашем харнесе

1. Распакуйте архив целиком в постоянную директорию **вне проверяемого проекта**.
2. Один раз подключите `skills/canton-daml-audit/SKILL.md` через механизм навыков вашего харнеса либо попросите агента прочитать этот файл по абсолютному пути. Если харнес поддерживает каталог навыков, зарегистрируйте папки из `skills/`, сохраняя доступ к полному набору. Не копируйте один SKILL.md без соседних `rules/`, `scripts/` и `templates/`: ссылки в навыках относительные.
3. Затем достаточно задачи:

```text
Проанализируй Daml-контракты для Canton в /absolute/path/to/my-project,
используя canton-daml-audit. Подготовь отчёт с проверенными выводами
и явно перечисленными неопределённостями.
```

Без механизма установки навыков используйте переносимый вариант:

```text
Прочитай /absolute/path/to/canton-daml-audit-kit/skills/canton-daml-audit/SKILL.md
и выполни описанный аудит проекта /absolute/path/to/my-project.
```

Агент запускает индексатор, читает сводку, загружает правила и исходники по мере необходимости, проверяет гипотезы и формирует отчёт. Сам по себе запуск Python-сканера создаёт **очередь для анализа**, а не законченный аудит: семантическую проверку выполняет ваша модель в вашем харнесе.

Поддержка автоподключения skills зависит от харнеса. Для ручного варианта достаточно агента, который умеет читать локальные файлы и запускать Python. Установка не изменяет конфигурацию вашего агента автоматически.

## Запуск скриптов вручную

Базовый режим требует **Python 3.10+**, только стандартную библиотеку. Проверено на Python 3.11 / Linux. Не нужны Daml SDK, npm, Docker, tree-sitter, API-ключи или доступ к сети.

Из директории распакованного набора:

```bash
python3 scripts/scan.py "/absolute/path/to/my-project"
```

Это единственный обязательный аргумент. Скрипт напечатает путь к новой временной директории результатов. Для постоянного места явно задайте **новую**, ещё не существующую директорию вне проекта:

```bash
python3 scripts/scan.py "/absolute/path/to/my-project" \
  --out "/absolute/path/to/audit-output/run-001"
```

Прочитайте `overview.md` и `summary.json` из напечатанного каталога. Затем запросите ограниченный контекст:

```bash
python3 scripts/context.py "/absolute/path/to/audit-output/run-001" \
  --topic authorization --limit 8 --max-chars 16000
```

Темы: `authorization`, `privacy`, `keys`, `atomicity`, `interfaces`, `topology`. Для следующей порции передайте `--offset` со значением `next_offset` из ответа. Для одной точки используйте `--id <candidate-id>`. `--radius` задаёт число строк вокруг неё. Лимит символов не является точным лимитом токенов; строки длиннее 300 символов помечаются как обрезанные. Если один фрагмент не помещается, уменьшите radius или увеличьте бюджет.

После содержательной проверки заполните копию `templates/findings.json` и создайте отчёт:

```bash
python3 scripts/report.py "/absolute/path/to/audit-output/run-001" \
  "/absolute/path/to/findings.json" \
  --out "/absolute/path/to/report.md"
```

Все поля описаны в `schemas/findings.schema.json`. Шаблон содержит учебные значения: замените их реальными. `evidence` — короткая точная цитата из одной строки исходника рядом с `line`. Один вывод может объединять несколько `candidate_ids`; вручную найденный вывод может иметь пустой список. Статусы: `CONFIRMED`, `FALSE_POSITIVE`, `UNCERTAIN`. Для подтверждения укажите влияние и реально выполненную проверку. Существующий отчёт не перезаписывается.

Отчёт автоматически показывает число ещё не рассмотренных кандидатов. Валидатор проверяет структуру, хеши и привязки к исходникам, но не доказывает правильность вывода аналитика. Для off-ledger/config/topology-находок добавьте отдельное приложение: текущая автоматическая проверка anchors принимает только Daml-файлы из индекса.

## Что входит

```text
AGENTS.md                         краткий вход для совместимых агентов
skills/
  canton-daml-audit/               полный процесс
  canton-daml-authorization/       делегирование и контроллеры
  canton-daml-privacy/             видимость и раскрытие данных
  canton-daml-keys/                ключи и уникальность
  canton-daml-atomicity/           время, арифметика, повторы, contention
  canton-daml-interfaces/          интерфейсы и обновления пакетов
  canton-daml-topology/            границы доверия Canton/Splice
  canton-daml-verify/              опровержение гипотез и отчёт
rules/                            общий процесс и тематические проверки
scripts/
  scan.py                         индекс и очередь кандидатов
  context.py                      порционная выборка исходников
  report.py                       валидация записей и Markdown-отчёт
  common.py                       обход файлов, хеши, лексическая маска
  build_parser.py                 опциональная сборка экспериментального парсера
  extract_ast.py                  опциональная структурная выборка
  benchmark.py                    измерение размера контекста
schemas/                          формат выводов
samples/                          синтетический пример данных и отчёта
references/                       версионные первичные источники
experimental/                     исходники shallow tree-sitter grammar
tests/                            проверки локальных инструментов
```

Выход индексатора:

- `summary.json`: объём, версии SDK из manifests, ограничения и пропуски;
- `overview.md`: короткая стартовая сводка;
- `inventory.jsonl`: файлы, хеши, module/import и лексические anchors template/interface/choice;
- `candidates.jsonl`: точки проверки с темой, вопросом и стабильным ID для данного path/line/rule.

## За счёт чего экономятся токены

1. Инвентаризация, удаление комментариев/строковых литералов из поиска и выборка контекста выполняются кодом, а не рассуждением модели над полным исходником.
2. Сначала читаются overview и summary; полный JSONL остаётся на диске.
3. Загружаются правила только текущей темы. Не нужно вставлять все навыки и базу правил в каждый запрос.
4. Хеши защищают от анализа устаревших фрагментов. Один индекс повторно используется между темами, пока исходники не изменились.
5. Готовые скрипты не приходится заново генерировать для каждого проекта. Форматирование и проверка отчёта также детерминированы.

Контрольный прогон на локальном snapshot `splice-amulet`: 22 Daml-файла, 304 299 байт, 34 template, 79 choice. Стартовые summary + overview: 1 456 байт; пример порции из двух authorization-кандидатов: 3 526 байт. Это **размеры артефактов**, не замер токенов или стоимости полного аудита. Сопоставимый анализ потребует дополнительных фрагментов и чтения бизнес-логики. Все 1 009 найденных лексических точек — кандидаты, не 1 009 уязвимостей. См. `VALIDATION.md`.

## Границы исполнения и покрытия

Базовые `scan.py`, `context.py`, `report.py` не делают сетевых запросов и не запускают subprocess, сборки, хуки, код проекта или ledger-команды. Читаются `.daml` и `daml.yaml`, результаты пишутся отдельно; существующие результаты не перезаписываются. Симлинки не обходятся, не-регулярные файлы отклоняются. Директории `.git`, `.daml`, `node_modules`, `venv`, `.venv`, `target`, `dist`, `build` и другие перечисленные в summary каталоги пропускаются. Анализ зависимостей при необходимости требует отдельного явно выбранного дерева исходников.

По умолчанию test/script/example-файлы включены и помечаются эвристически. `--exclude-tests` исключает пути по имени и фиксирует пропуск; используйте его только если это соответствует области проверки. Лимиты: 20 000 подходящих файлов и 2 МиБ на файл; параметры `--max-files`/`--max-bytes` позволяют изменить их. Код выхода 0 означает завершённый проход, 2 — ошибку, 3 — отсутствие просканированных Daml-файлов. При ошибке частичный вывод не следует считать полным.

Базовая выборка лексическая: это не Daml-компилятор, не полный AST или call graph. Она не доказывает достижимость, отсутствие уязвимостей, корректность топологии или развёрнутой версии. Конфигурации Canton, off-ledger код, бизнес-требования и зависимости нужно читать адресно в ходе проверки. Список кандидатов намеренно шире списка реальных дефектов.

Работа в вашем харнесе сохраняет его границы доверия и политику данных. Сами скрипты не отправляют исходники наружу, но выбранные агентом фрагменты обрабатываются той моделью и тем провайдером, которыми пользуется ваш харнес. Это не новая песочница для враждебных репозиториев; используйте обычную изоляцию вашей среды и стабильный snapshot исходников.

## Необязательный экспериментальный парсер

Предыдущий tree-sitter-прототип сохранён в исходниках. Он не нужен для запуска набора. Готовые нативные библиотеки в архив не включены. Python binding фиксирован на версии, совместимой с прототипом; это не рекомендация последней версии библиотеки.

Если нужен именно этот режим, в доверенной среде установите дополнительную зависимость и соберите **исходник из набора**, а не код проверяемого проекта:

```bash
python3 -m venv .parser-venv
.parser-venv/bin/python -m pip install -r experimental/requirements.txt
python3 scripts/build_parser.py --out "/absolute/path/to/new-parser-build"
.parser-venv/bin/python scripts/extract_ast.py "/absolute/path/to/audit-output/run-001" \
  --so "/absolute/path/to/new-parser-build/daml.so" \
  --out "/absolute/path/to/surface.jsonl"
```

Установка зависимости — явная отдельная операция с сетью, если пакет не подготовлен локально. `build_parser.py` вызывает доверенный системный C-компилятор. Linux проверен; для macOS предусмотрено расширение `.dylib`, но этот вариант не тестировался; Windows для нативного режима не поддержан. Базовые скрипты от нативного режима не зависят.

Грамматика не реализует полноценный offside/layout parsing и разбор выражений. На контрольном прогоне получилось 219 recovery/error-узлов при 34 template и 79 choice. Нельзя считать эти ошибки заведомо безвредными; ноль ошибок тоже не доказывает полноту. Для выводов проверяйте исходники и поведение соответствующего SDK.

## Проверка набора и публикация

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют пропуск комментариев/строк, вложенные комментарии, отсутствие выполнения проекта, симлинки, лимиты, неизменность исходников, устаревшие хеши, валидацию anchors и учёт нерассмотренных кандидатов. Для повторения измерений объёма: `python3 scripts/benchmark.py /path/to/scan-directory`.

Набор подготовлен для публикации как переносимая библиотека навыков и правил для **Daml/Canton**, а не как отдельный харнес. В архив не входят частные аудиторские отчёты, исходники проверяемых репозиториев, переписки, ключи, credentials, виртуальные окружения и скомпилированные бинарники. Примеры синтетические. `PROVENANCE.md` описывает перенос наработок и исправления; `LICENSE` и `THIRD_PARTY_NOTICES.md` — условия распространения. Публикуйте весь каталог с сохранением структуры и этих файлов.
